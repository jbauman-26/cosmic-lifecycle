# Cosmic Lifecycle and the Graphed CLI, command by command

Graphed's CLI (0.0.26, checked 2026-11-24) runs your marketing on Graphed's cloud. Cosmic Lifecycle gives you the same command surface on your own machine, your own GitHub and your own database, and stores totals only. Every Graphed command has a Cosmic equivalent below. Where the two work differently, the Notes column says how and why.

| Graphed | Cosmic Lifecycle | Notes |
|---|---|---|
| `login`, `logout`, `accounts list` | `status` | There is no account to log in to. `status` is the first check: setup, sources, trust line, daily sync, updates. |
| `config set/get/list/unset` | `config set/get/list/unset` | `registry.uri`, `deploy.repo`, `update.check`, and since 0.11.0 the owner's choices: `reconcile.tolerance.klaviyo_orders` (3), `reconcile.tolerance.ga4_purchases` (15), `reconcile.attributed_share_flag` (60), `reconcile.freshness_days` (2), `query.row_cap` (1000) and `metrics.default_days` (90). Each defaults to the value the CLI always used. `get` and `list` show the default when a key is not set. |
| `init` | `init` | A local database, or your own Postgres with `--database-url-env`. |
| `clone` | `deploy --write DIR` | Writes the sync project files locally. Clone an existing sync repo with `gh repo clone`. |
| `deploy` | `deploy` | A private repo on your GitHub with a daily GitHub Actions sync. Prints the plan first; creates nothing without `--yes`. |
| `projects list/create/delete` | `provision neon`, `deploy`, `config get deploy.repo` | `provision neon` creates the managed Postgres in your own Neon account; `deploy` creates the sync repo. Deleting either stays your call. |
| `jobs list/run` | `jobs list/run` | Runs of the daily sync, with the success streak toward the 7-day release test. |
| `logs`, `logs --follow` | `logs`, `logs --cloud`, `logs --follow` | Local sync history, one row per source per run, with an error code on a failed run (`key_rejected`, `rate_limited`, `scope_denied`), or the log of the last GitHub Actions run. `--follow` waits for a running sync to finish, then shows its log. Graphed streams service logs line by line. A sync here is one short job, so there is no stream to tail. |
| `services list` | `serve` | The dashboard and a read-only JSON API (`/api/metrics/:name`, `/api/reconcile`, `/api/flows`, `/api/audit`) on 127.0.0.1. |
| `exec`, `dev run` | `exec -- COMMAND` | Runs any command with your keys and store settings in its environment, so a script or agent can use them without seeing or pasting them. |
| `secrets set/list/delete` | `secrets set/list/delete` | macOS keychain or `LIFECYCLE_*` variables. `set` reads from an environment variable, never an argument. Values are never printed. |
| Per-pipeline sync schedules | `sync --only SOURCE` | Syncs one built-in source (or a comma list) on its own schedule. Each source keeps its own run row. Asking for a source that is not connected fails with `not_connected` rather than doing nothing. Reconcile runs after every sync. |
| Removing a source | `disconnect SOURCE [--delete-data]`, `warehouse disconnect SLUG` | Removes a built-in source's settings and saved keys. Its data stays unless `--delete-data`. The disconnect is logged, so the freshness check stops counting the source. |
| `sources list/catalog` | `sources list/catalog` | Klaviyo, Shopify, GA4, Stripe and Meta Ads natively. Meta Ads is read only: daily spend and Meta's own attributed purchases by campaign, written from the API docs and not yet run on a live ad account. Shopify, Klaviyo and GA4 are reconciled against each other. Stripe adds subscriptions, MRR and repeat payments. |
| 750+ managed source pipelines | `warehouse connect/sync`, `warehouse add-api`, `sources import NAME --csv FILE` | 98 tools in the catalog, 96 of them ranked by usage. 25 have warehouse connectors (dlt, one schema per tool), written from vendor docs and not yet run on a real account. 0.12.0 added Brevo, Privy, Okendo, Loox and Fairing, and left Postscript, Attentive, Rebuy and Northbeam planned with the reason each (enterprise-only keys, no read endpoints, storefront-only API, export jobs only). Google Ads and Google Search Console are planned as built-in sources that need Google sign-in; there is no connector code for them. The app or server can point the CLI at its own uv with `LIFECYCLE_UV_PATH` and `LIFECYCLE_UV_CACHE_DIR`, so an owner installs nothing; without any uv the code is `missing_uv`. Any REST API can be added from a spec. Anything else comes in as daily totals from CSV. Personal data is removed before loading unless you opt in. |
| `warehouse schema/query`, `databases list/query` | `schema`, `query`, `warehouse schema/query` | Read-only, one statement, 1,000-row cap by default (`query.row_cap`), system tables blocked. On Postgres a query runs in the store's own schema: the connection's, or `LIFECYCLE_DB_SCHEMA`. Before 0.12.0 it was forced to `public`. Warehouse queries on a local DuckDB file also block file and network access. |
| `tools catalog/run/get/abort` | `tools catalog/run/get/runs` | Read-only Klaviyo and Shopify API tools on your own keys. Runs are saved and fetched by id. Calls finish in seconds, so there is nothing to abort. No credits and no markup. |
| `tools run` with any `apify:`, `kie:`, `fal:` or `scrapecreators:` ref (0.0.26) | `tools run REF --wait`, `tools providers` | The same four providers and the same ref shapes. The call goes from your machine to the provider on your own key, so you sign up with each one you use and pay it directly. A wait that times out never starts the job again. Written from each provider's API docs and tested against recorded answers. Not yet run against a live account. |
| `files ls/cat` | `files ls/cat` | Every report, dashboard and plan the CLI writes, kept by date. |
| `storage upload/download/url` | `files put/get/path`, `files pull` | `pull` downloads the dashboard the daily sync uploads to your own private repo. No public URLs, because the numbers are a brand's revenue. |
| MCP `whoami`, `list_source_catalog`, `explore_schema`, `query` | `lifecycle mcp` | Same names where they apply. `metric` and `list_metrics` include the owner's saved numbers. Plus `metric`, `list_metrics`, `metric_candidates`, `list_tool_catalog`, `run_tool`, `list_files`, `read_file`, `reconcile`, `revenue_per_flow`, `audit_flows`. |
| Verified metrics (their blog, January 2026) | `metrics list/show/run/candidates`, `metrics save/delete` | Fixed SQL per metric. Repeated custom queries become candidates for new metrics. Since 0.12.0 the owner can save one as a named number: `metrics save NAME --sql '...' [--title --unit]`. Saved numbers are kept in the store's own database, listed as saved by the owner, run read-only with the trust line, and cannot take a built-in metric's name (`reserved_name`). |
| `publish_query`, embedded dashboards | `dashboard`, `serve` | A local HTML file, or a local web page that updates on reload. |
| `plugins list/search/show/add/validate` | `kits list/search/show/add/validate` | Kits come from [cosmic-registry](https://github.com/jbauman-26/cosmic-registry), refreshed every 10 minutes. |
| Skills page "Copy setup prompt" | `kits prompt NAME` | |
| `skills sync/status/push/delete/uninstall` | `skills sync/status/uninstall` | `/lifecycle` and `/lifecycle:kits:NAME` in Claude Code and Cursor. Kits and skills are edited in the registry rather than pushed per account. |
| `docs` | `docs` | `quickstart`, `setup`, `agents`, `kits`, `commands`, `tools`, `warehouse`, `troubleshooting`. |
| llms.txt | [llms.txt](../llms.txt) | Generated from `docs quickstart`. CI fails if they differ. |
| `tickets open/list/show/respond/close/reopen/subscribe` (replaced `feedback` in 0.0.26) | `feedback` | A prefilled GitHub issue with versions only. Replies and status live on the issue. |
| App home: six-step workspace checklist | `status`, `dashboard` | Six setup steps with done or to do, and the one command that finishes each. Hidden once all six are done. |
| Update notices | `status` | Checks GitHub at most once a day. The repo is private, so most installs cannot see the release list: the check then says nothing and waits a day. The app and Cosmic Cloud update the CLI they carry. Turn off with `config set update.check false`. |
| One job at a time per workspace | A write lock per home folder | `sync`, `connect`, `init`, `reconcile`, `disconnect`, `metrics save` and the warehouse writes take `write.lock`. A second writer waits 10 seconds (`LIFECYCLE_LOCK_WAIT_MS`), then fails with `busy`. Reads are not blocked. A lock left by a dead process is cleared. Postgres stores lock themselves. |
| Keys held by the platform | `connect SOURCE --key-env NAME` without a keychain | Since 0.12.0 the connect passes once the key checks out, saves settings only, and reports `keyStorage: environment` with the `LIFECYCLE_*` variable the caller must set at sync time. This is how the app and Cosmic Cloud call it. |
| Forward-deployed engineers | [Setup with Jake at NorthSignal](https://northsignal.studio/lifecycle) | A person sets it up for you, starting with a free call. |

## Where the two differ on purpose

- **Hosting.** A hosted pilot, Cosmic Cloud, runs the same CLI for brands that want it managed. Each brand gets its own database schema and role, encrypted keys, a daily sync and a dashboard behind sign-in. It is in pilot and onboards brands one at a time under signed terms. Setup starts with a call: https://northsignal.studio/lifecycle
- **Where things run.** Graphed runs your jobs and services on its servers. Cosmic runs them on your machine and in your GitHub account, so there is no server of ours holding your data.
- **How tools are paid for.** Graphed charges plan credits per tool call, across 259 tools from 16 providers (their /tools page, 2026-11-24), on one login. Cosmic calls each provider directly on your own key, at no cost from us. That covers Klaviyo and Shopify with built-in tools, and Kie, fal, Apify and ScrapeCreators by ref. It means a signup per provider, and it leaves out the providers Graphed fronts that have no open ref here, such as Apollo, DataForSEO, Exa and HeyGen.
- **How sources connect.** Graphed resells about 700 Fivetran pipelines into its ClickHouse warehouse. Cosmic connects five natively (Klaviyo, Shopify, GA4, Stripe, Meta Ads), loads 25 more raw into your own database with dlt (Apache 2.0), and lists 73 more as planned with a reason each. Raw loads strip personal data unless you pass --keep-personal-data.
- **Price.** The CLI is free and MIT licensed. There is no paid plan.
