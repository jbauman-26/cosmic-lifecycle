# Cosmic Lifecycle commands, by job

What each job is called in Cosmic Lifecycle, with how it works and why. Everything runs on your own machine, your own GitHub and your own database, and stores totals only.

| Job | Command | Notes |
|---|---|---|
| Sign in and see the account | `login`, `logout`, `cloud status`, `status` | Since 0.13.0, `login --token-env VAR` signs a machine in to the store's Cosmic Cloud account with a store token, and `--cloud` on `query`, `schema`, `metrics list/run`, `sources list`, `sync` and `logs` asks Cloud. Logging in is optional: everything else runs on this machine. `status` is still the first check. |
| Settings | `config set/get/list/unset` | `registry.uri`, `deploy.repo`, `update.check`, and since 0.11.0 the owner's choices: `reconcile.tolerance.klaviyo_orders` (3), `reconcile.tolerance.ga4_purchases` (15), `reconcile.attributed_share_flag` (60), `reconcile.freshness_days` (2), `query.row_cap` (1000) and `metrics.default_days` (90). Each defaults to the value the CLI always used. `get` and `list` show the default when a key is not set. |
| Set up the database | `init` | A local database, or your own Postgres with `--database-url-env`. |
| Get the sync project files | `deploy --write DIR` | Writes the sync project files locally. Clone an existing sync repo with `gh repo clone`. |
| Run the daily sync from GitHub | `deploy` | A private repo on your GitHub with a daily GitHub Actions sync. Prints the plan first; creates nothing without `--yes`. |
| Databases and sync repos | `provision neon`, `deploy`, `config get deploy.repo` | `provision neon` creates the managed Postgres in your own Neon account; `deploy` creates the sync repo. Deleting either stays your call. |
| Runs of the daily sync | `jobs list/run` | Runs of the daily sync, with the success streak toward the 7-day release test. |
| Sync history and logs | `logs`, `logs --cloud`, `logs --actions`, `logs --follow` | Local sync history, one row per source per run, with an error code on a failed run (`key_rejected`, `rate_limited`, `scope_denied`, `loader_failed`). `--cloud` shows the runs on Cosmic Cloud, `--actions` the log of the last GitHub Actions run. `--follow` waits for a running sync to finish, then shows its log. A sync here is one short job, so there is no stream to tail. |
| A live view and a local API | `serve` | The dashboard and a read-only JSON API (`/api/metrics/:name`, `/api/reconcile`, `/api/flows`, `/api/audit`) on 127.0.0.1. |
| Run a command with the store's keys | `exec -- COMMAND` | Runs any command with your keys and store settings in its environment, so a script or agent can use them without seeing or pasting them. |
| Keys | `secrets set/list/delete` | macOS keychain or `LIFECYCLE_*` variables. `set` reads from an environment variable, never an argument. Values are never printed. |
| Sync one source on its own | `sync --only SOURCE` | Syncs one built-in source (or a comma list) on its own schedule. Each source keeps its own run row. Asking for a source that is not connected fails with `not_connected` rather than doing nothing. Reconcile runs after every sync. |
| Remove a source | `disconnect SOURCE [--delete-data]`, `warehouse disconnect SLUG` | Removes a built-in source's settings and saved keys. Its data stays unless `--delete-data`. The disconnect is logged, so the freshness check stops counting the source. |
| Connected sources | `sources list/catalog` | Klaviyo, Shopify, GA4, Stripe and Meta Ads natively. Meta Ads is read only: daily spend and Meta's own attributed purchases by campaign, written from the API docs and not yet run on a live ad account. Shopify, Klaviyo and GA4 are reconciled against each other. Stripe adds subscriptions, MRR and repeat payments. |
| Sources beyond the built-in five | `warehouse connect/sync`, `warehouse add-api`, `sources import NAME --csv FILE` | 98 tools in the catalog, 96 of them ranked by usage. 25 have warehouse connectors (dlt, one schema per tool), written from vendor docs and not yet run on a real account. 0.12.0 added Brevo, Privy, Okendo, Loox and Fairing, and left Postscript, Attentive, Rebuy and Northbeam planned with the reason each (enterprise-only keys, no read endpoints, storefront-only API, export jobs only). Google Ads and Google Search Console are planned as built-in sources that need Google sign-in; there is no connector code for them. The app or server can point the CLI at its own uv with `LIFECYCLE_UV_PATH` and `LIFECYCLE_UV_CACHE_DIR`, so an owner installs nothing; without any uv the code is `missing_uv`. Any REST API can be added from a spec. Anything else comes in as daily totals from CSV. Personal data is removed before loading unless you opt in. |
| Look at tables and query them | `schema`, `query`, `warehouse schema/query` | Read-only, one statement, 1,000-row cap by default (`query.row_cap`), system tables blocked. On Postgres a query runs in the store's own schema: the connection's, or `LIFECYCLE_DB_SCHEMA`. Before 0.12.0 it was forced to `public`. Warehouse queries on a local DuckDB file also block file and network access. |
| Built-in tools | `tools catalog/run/get/abort/runs` | Read-only Klaviyo and Shopify API tools on your own keys. Runs are saved and fetched by id, each with the request that was sent. `abort` stops an Apify or fal job that is still going. No credits and no markup. |
| Provider tools by ref (Kie, fal, Apify, ScrapeCreators) | `tools run REF --wait`, `tools providers` | The call goes from your machine to the provider on your own key, so you sign up with each one you use and pay it directly. A wait that times out never starts the job again. Written from each provider's API docs and tested against recorded answers. Not yet run against a live account. |
| Files the CLI wrote | `files ls/cat` | Every report, dashboard and plan the CLI writes, kept by date. |
| Move files in and out | `files put/get/path`, `files pull` | `pull` downloads the dashboard the daily sync uploads to your own private repo. No public URLs, because the numbers are a brand's revenue. |
| MCP for an agent | `lifecycle mcp` | `whoami`, `list_source_catalog`, `explore_schema` and `query`. `metric` and `list_metrics` include the owner's saved numbers. Plus `metric`, `list_metrics`, `metric_candidates`, `list_tool_catalog`, `run_tool`, `list_files`, `read_file`, `reconcile`, `revenue_per_flow`, `audit_flows`. |
| Verified metrics | `metrics list/show/run/candidates`, `metrics save/delete` | Fixed SQL per metric. Repeated custom queries become candidates for new metrics. Since 0.12.0 the owner can save one as a named number: `metrics save NAME --sql '...' [--title --unit]`. Saved numbers are kept in the store's own database, listed as saved by the owner, run read-only with the trust line, and cannot take a built-in metric's name (`reserved_name`). |
| Dashboards | `dashboard`, `serve` | A local HTML file, or a local web page that updates on reload. |
| Kits | `kits list/search/show/add/validate` | Kits come from [cosmic-registry](https://github.com/jbauman-26/cosmic-registry), refreshed every 10 minutes. |
| A setup prompt for a kit | `kits prompt NAME` | |
| Skills | `skills sync/status/push/delete/uninstall` | `/lifecycle` and `/lifecycle:kits:NAME` in Claude Code and Cursor. Kits are edited in the registry. A store's own skills are pushed to its Cosmic Cloud account with `skills push DIRECTORY` and installed by `skills sync` when logged in. |
| Docs | `docs` | `quickstart`, `setup`, `agents`, `kits`, `commands`, `tools`, `cloud`, `warehouse`, `troubleshooting`. |
| A file for agents to read | [llms.txt](../llms.txt) | Generated from `docs quickstart`. CI fails if they differ. |
| Feedback and support | `feedback` | A prefilled GitHub issue with versions only. Replies and status live on the issue. |
| Setup checklist | `status`, `dashboard` | Six setup steps with done or to do, and the one command that finishes each. Hidden once all six are done. |
| Update notices | `status` | Checks GitHub at most once a day. The repo is private, so most installs cannot see the release list: the check then says nothing and waits a day. The app and Cosmic Cloud update the CLI they carry. Turn off with `config set update.check false`. |
| One writer at a time | A write lock per home folder | `sync`, `connect`, `init`, `reconcile`, `disconnect`, `metrics save` and the warehouse writes take `write.lock`. A second writer waits 10 seconds (`LIFECYCLE_LOCK_WAIT_MS`), then fails with `busy`. Reads are not blocked. A lock left by a dead process is cleared. Postgres stores lock themselves. |
| Keys kept by an app or a server | `connect SOURCE --key-env NAME` without a keychain | Since 0.12.0 the connect passes once the key checks out, saves settings only, and reports `keyStorage: environment` with the `LIFECYCLE_*` variable the caller must set at sync time. This is how the app and Cosmic Cloud call it. |
| Setup done for you | [Setup with Jake at NorthSignal](https://northsignal.studio/lifecycle) | A person sets it up for you, starting with a free call. |

## Choices made on purpose

- **Hosting.** A hosted pilot, Cosmic Cloud, runs the same CLI for brands that want it managed. Each brand gets its own database schema and role, encrypted keys, a daily sync and a dashboard behind sign-in. It is in pilot and onboards brands one at a time under signed terms. Setup starts with a call: https://northsignal.studio/lifecycle
- **Where things run.** Cosmic runs your jobs and services on your machine and in your GitHub account, so there is no server of ours holding your data unless you choose Cosmic Cloud.
- **How tools are paid for.** Cosmic calls each provider directly on your own key, at no cost from us. That covers Klaviyo and Shopify with built-in tools, and Kie, fal, Apify and ScrapeCreators by ref. It means a signup per provider you use, and providers with no open ref here are not covered.
- **How sources connect.** Cosmic connects five natively (Klaviyo, Shopify, GA4, Stripe, Meta Ads), loads 25 more raw into your own database with dlt (Apache 2.0), and lists 73 more as planned with a reason each. Raw loads strip personal data unless you pass --keep-personal-data.
- **Price.** The CLI is free and MIT licensed. There is no paid plan.
